What is this tool?

RAT looks inside a Git repository - the version-controlled folder where a software project lives - and shows who changed what, when, and by how much. Every number comes from Git's own history, so the figures match what Git itself reports.

You add a repository once; it is indexed in the background and then you can explore it through five tabs. All numbers are computed over the commit set - a chosen group of commits - which by default means the whole history.

Adding a repository

There are two ways, both on the home page:

WayHowGood to know
Clone from URL Paste the web address of a public repository (GitHub, GitLab, Bitbucket...) and press Clone & index. The complete history is downloaded, so big projects can take a few minutes. Private repositories won't work - the tool never logs in anywhere.
Upload a zip Upload a .zip of a repository folder that includes its hidden .git folder. GitHub's green Download ZIP button does not include the history, so those zips cannot be analysed. To make a working zip: clone the repository on your computer, then zip the whole cloned folder (hidden files included) - see If something goes wrong.

Indexing runs in the background on a progress page; you can leave it open or come back later - the repository stays listed on the home page either way.

The five tabs

TabWhat it showsUse it to...
Overview The big picture: key totals, activity over time, the most-changed files and the top authors - all for the current commit set. Get oriented. This is the page to show someone who has never seen the repository.
Files Every file that changed, one row each, with a column per metric. Search by path, click a column header to sort, export everything to a spreadsheet. Find the busiest or biggest files, or the files only one person touches.
Directories The same metrics but organised like folders. Each folder's numbers include everything inside it, at any depth. Explore a project structure folder by folder.
Commits The raw list of commits, newest first, with a search box. See the actual history - and tick commits to build a custom commit set.
Authors Who did what: commits, lines added/removed, churn and ownership per person. See each person's contribution - and merge duplicate names or emails.

What the numbers mean

TermIn plain English
Commit set (H) The group of commits the numbers are computed from. By default: all history. You can narrow it with the filter bar or by hand-picking commits.
Reference The point in history to count from - normally the latest commit (HEAD). Change it to measure from an older point, a branch or a tag.
|H| How many commits are in the current commit set. "Per commit" figures divide by this.
Added / Removed How many lines the commits added and deleted, counted by Git's diff. Binary files (images, PDFs...) are skipped, and pure renames are followed to the new name.
Growth (Δ) Added minus removed. Positive: the codebase grew by that many lines. Negative: it shrank.
Churn (λ) Added plus removed - the total amount of change. A file edited many times has high churn even if it never grows.
Modifications (n) How many of the commits in the set actually changed this file. A pure rename doesn't count as a modification.
Mod frequency (η) Modifications divided by |H| - the fraction of commits that touched the file. 0.10 means one in ten commits changed it.
Churn rate (ρ) Churn divided by |H| - the average number of changed lines per commit in the set.
Ownership (ω) An author's share of all changed lines on the file or folder, as a percentage. Answers "who knows this code best?"
Author identity Git recognises people by name + email, so one person with two emails looks like two authors. The tool merges them automatically using the project's .mailmap file, and you can merge more by hand on the Authors tab.

Filtering & commit sets

The bar at the top of every dashboard page decides what gets counted:

ControlEffect
Reference Count history from this commit. Leave it as HEAD (the latest) unless you deliberately want an older point.
From / To Only count commits inside this date range (To itself is not included). The quick buttons "30 days", "90 days" and "1 year" fill this in for you.
Author Only one person's commits - applied everywhere on the repository until you clear it.
Clear Removes all filters and goes back to "all history, everyone".
Manual commit set On the Commits tab, tick individual commits and press "Apply checked commits" - every tab then shows only those commits. The orange chip at the top shows when a manual set is active, with a link to edit it.

Common tasks

I want to...Do this
See who contributed the most Open Overview and look at the Authors table, or the Authors tab for the full breakdown.
See only the last 30 days Click the 30 days button in the filter bar, then Apply.
Find the files that change the most Files tab, then click the Churn or Mods column header to sort.
Focus on one person Pick them in the Author dropdown, then Apply.
Fix one person appearing twice Authors tab → Merge authors: choose the two identities and press Merge. It can be undone.
Get the data into Excel Press Export CSV on the Overview or Files tab - it downloads the current (filtered) numbers.
Look at one part of the project Directories tab, then click through the folders.

If something goes wrong

What you seeWhat it means and what to do
"no git repository found" when uploading a zip The zip has no Git history inside. This almost always means it came from GitHub's green Download ZIP button, which only includes the current files. Fix: clone the repository by URL instead, or zip a local clone (hidden .git folder included).
Clone fails or times out Check the URL is the full address of a public repository. Private repositories can't be reached because the tool never logs in. Big projects simply take a while.
A repository is stuck on "working" Large histories take minutes. The progress page updates by itself - you can leave and come back; indexing continues in the background.
Everything shows zero Your filters probably exclude everything - for example a date range in the future, or an author with no commits in the range. Press Clear in the filter bar.
